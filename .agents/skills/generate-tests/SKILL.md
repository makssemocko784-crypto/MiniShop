# Генерація тестів MiniShop

Усі шляхи нижче відраховуй від кореня проєкту.

## Контекст і межі

1. Прочитай `docs/app-requirements.md`, `docs/guardrails.md`, відповідні функції застосунку та наявні тести. Дотримуйся guardrails протягом усієї роботи.
2. Отримай контекст через `minishop-kb.search_notes` із параметром `query`, що відповідає функції або вимозі, наприклад `JSON` для збереження й завантаження. Використовуй доступний MCP-інструмент; не вигадуй результатів. Якщо інструмент недоступний або повертає помилку, повідом про це та продовжуй за локальними вимогами, якщо контексту достатньо. База знань доповнює, але не замінює вимоги та вказівки користувача.
3. Визнач реалізовані FR у межах запиту. Для початкової версії перевіряй FR-01, FR-02, FR-05 і FR-06. Не додавай тести для майбутніх FR-03, FR-04 і FR-07 без відповідного запиту.

## Створення тестів

- Створюй або доповнюй лише файли всередині `tests/`, використовуючи pytest та наявні інтерфейси функцій. Не додавай бібліотек або складної тестової архітектури.
- Перевіряй поведінку за вимогами: успішні операції, граничні значення, відхилення некоректних даних та обробку помилок. Для додавання перевіряй назву, додатну цілу кількість, унікальний ID і початковий статус; для перегляду — всі поля та порожній список.
- Для JSON перевіряй збереження й відновлення всіх полів, відсутній файл, пошкоджений JSON, некоректну структуру, дублікати ID, недопустимі значення та помилки доступу. Перевіряй, що помилка не змінює поточний список і не перезаписує пошкоджений файл; некоректне введення не запускає автозбереження.
- Ізолюй файлові операції через `tmp_path`, а консольне введення, виведення та залежності — через `monkeypatch` і `capsys`, де потрібно. Не читай і не перезаписуй робочий `products.json`. Тимчасові дані тестів допускаються лише в тимчасовому каталозі pytest.
- Не змінюй бізнес-логіку без явного підтвердження користувача. Якщо тест виявив дефект, залиш перевірку очікуваної за вимогами поведінки та повідом про дефект; не підлаштовуй очікування під помилку реалізації.
- Не змінюй MCP, hooks, документацію, конфігурацію або файли застосунку в межах генерації тестів. Дотримуйся заборон guardrails, зокрема щодо видалення захищених файлів і небезпечних Git-команд.

## Запуск і звіт

Запусти створені або змінені тести через доступний інтерпретатор проєкту, наприклад у PowerShell:

```powershell
.venv/Scripts/python.exe -B -m pytest -q -p no:cacheprovider tests/test_shop.py tests/test_storage.py
```

Підстав фактичні шляхи створених тестів. Не встановлюй залежності й не перебудовуй середовище без окремого дозволу. Якщо Python, pytest або потрібні ресурси недоступні, повідом точну причину неможливості запуску. Якщо користувач заборонив запуск, дотримуйся цієї заборони й зазнач це у звіті.

У відповіді українською вкажи створені чи змінені тестові файли, покриті FR, команду запуску та фактичний результат: кількість успішних і невдалих тестів або причину, з якої запуск не відбувся. Окремо назви виявлені дефекти. Не заявляй про успіх без результату виконання.
