# Вимоги до застосунку MiniShop

## 1. Назва та опис

**MiniShop** — навчальний консольний застосунок мовою Python для ведення одного списку покупок із локальним збереженням даних у JSON.

## 2. Призначення та цільові користувачі

Призначення: облік запланованих покупок і відстеження їх придбання.

Цільові користувачі: користувачі, яким потрібен простий список покупок, та здобувачі освіти, які вивчають розробку програм на Python.

## 3. Межі проєкту

Застосунок підтримує один список покупок. Реєстрація користувачів, база даних і вебінтерфейс не передбачені.

## 4. Функціональні вимоги

| Код | Вимога |
| --- | --- |
| FR-01 | Додавання товару із назвою, кількістю та автоматично призначеним унікальним ID. Початковий статус — «Не придбано». |
| FR-02 | Перегляд усіх товарів із відображенням ID, назви, кількості та статусу. Для порожнього списку виводиться відповідне повідомлення. |
| FR-03 | Зміна статусу товару за ID між «Не придбано» та «Придбано». |
| FR-04 | Видалення товару зі списку за ID. |
| FR-05 | Автоматичне збереження поточного списку в локальний JSON-файл після кожної успішної зміни списку зі збереженням ID, назви, кількості та статусу кожного товару. |
| FR-06 | Завантаження списку з локального JSON-файлу з перевіркою структури та значень даних. Успішне завантаження замінює поточний список. За відсутності файлу застосунок починає роботу з порожнім списком. Якщо файл існує, але пошкоджений або містить некоректні дані, програма повідомляє про помилку, не перезаписує файл і не змінює поточний список. |
| FR-07 | Фільтрація товарів за статусом «Не придбано» або «Придбано» без зміни списку. |

## 5. Правила валідації

- Назва товару після видалення пробілів на початку й у кінці має бути непорожньою.
- Кількість має бути додатним цілим числом.
- ID має бути унікальним у межах списку, зокрема після завантаження даних.
- Статус може мати лише значення «Не придбано» або «Придбано».
- Операції за ID потребують наявності відповідного товару.
- Некоректні введені або завантажені дані відхиляються з повідомленням про помилку; поточний список залишається незмінним, автоматичне збереження не виконується. Пошкоджений JSON-файл або файл із некоректними даними не перезаписується.

## 6. Нефункціональні вимоги

- **Середовище:** локальна робота на Windows без потреби в мережевому підключенні.
- **Інтерфейс:** консольне введення команд і зрозумілі текстові повідомлення українською мовою.
- **Обробка помилок:** некоректне введення, невідомий ID, пошкоджений файл, некоректні дані у файлі та помилки доступу до файлів не повинні спричиняти аварійне завершення. За відсутності JSON-файлу застосунок починає роботу з порожнім списком. Якщо файл пошкоджений або містить некоректні дані, програма повідомляє про помилку, не перезаписує файл і не змінює поточний список.
- **Збереження між запусками:** після кожної успішної зміни списку дані автоматично зберігаються в JSON і мають відновлюватися під час подальшого завантаження, зокрема після перезапуску застосунку.
- **Тестування:** автоматизовані тести мають перевіряти реалізовані функціональні вимоги, валідацію та обробку основних помилок.
