# ПР6: мінімальна оркестрація агентів

Мета майбутнього виконання — реалізувати FR-07: фільтрацію товарів за статусом відповідно до `docs/app-requirements.md`. Цей документ лише описує процес; FR-07 на цьому етапі не реалізується.

Послідовність: **Developer → Tester → Reviewer**. Ролі працюють послідовно та передають результати наступній ролі.

| Роль | Вхідні дані | Дії | Результат |
| --- | --- | --- | --- |
| Developer | FR-07, поточний код, локальні правила, зауваження попередньої перевірки | Реалізує фільтрацію за статусом у межах вимог; виправляє отримані помилки. | Зміни коду й короткий опис поведінки для Tester. |
| Tester | FR-07, зміни Developer, попередні помилки | Використовує `generate-tests` за інструкціями навички; створює та запускає pytest-тести фільтрації й перевіряє регресії. | Звіт із командами, результатами та кроками відтворення помилок; передача Reviewer лише після успішних тестів. |
| Reviewer | FR-07, зміни коду й тестів, звіт Tester, локальні правила | Перевіряє відповідність вимогам, якість змін і дотримання Guardrails. Після схвалення використовує `document-change` для документування фактичних змін через MCP `minishop-kb`. | Схвалення та посилання на нотатку або перелік зауважень для Developer. |

## Інструменти та обмеження

- Усі ролі дотримуються локальних інструкцій і Guardrails перед діями та викликами інструментів; заборонені операції не обходять.
- MCP використовується для дозволеного доступу до бази знань; записи виконуються за правилами `document-change` і MCP. Помилки доступу фіксуються, успішний запис підтверджується результатом інструмента.
- Кожна передача містить актуальні зміни, результат перевірки та відкриті зауваження. Завершення потребує успішних тестів, схвалення Reviewer і документування змін.

## Повернення та повторна перевірка

Якщо Tester або Reviewer виявляє помилку, він повертає задачу **Developer** з описом проблеми й очікуваним результатом. Developer виправляє її, після чого обов’язково повторюється **Tester → Reviewer** для актуальних змін. Пропуск повторної перевірки заборонений; цикл триває до усунення всіх зауважень.
