# Guardrails — MiniShop

## 1. Призначення

Guardrails визначають правила безпечної роботи AI-агента Codex із кодом MiniShop та базою знань MiniShop-KB.

Дії агента поділяються на три категорії: allow, warn та block.

## 2. Allow — дозволені дії

- AL-01: Читання файлів застосунку MiniShop.
- AL-02: Створення нових тестів у каталозі `tests/`.
- AL-03: Запуск автоматизованих тестів pytest.

Ці дії дозволені без додаткового підтвердження.

## 3. Warn — дії, що потребують підтвердження

- WR-01: Зміна наявної бізнес-логіки у файлі `shop.py`.
- WR-02: Зміна архітектурних вимог у `docs/app-requirements.md`.
- WR-03: Оновлення архітектурних рішень у `Decisions/` бази знань.

Перед виконанням цих дій агент повинен отримати підтвердження користувача.

## 4. Block — заборонені дії

- BL-01: Видалення файлів із `Decisions/` бази знань MiniShop-KB.
- BL-02: Виконання `git push --force` та `git reset --hard`.
- BL-03: Видалення файлів `docs/app-requirements.md` і `docs/harness-requirements.md`.

Ці дії мають блокуватися незалежно від рішення агента.

## 5. Технічне забезпечення

Для реалізації block-правил передбачено використання pre-tool-use hook агентного середовища Codex.

У межах ПР4 буде реалізовано hook для правила BL-02. Решта правил підлягають перевірці відповідно до встановлених обмежень.

## 6. Перевірка

Для кожної категорії передбачено щонайменше три тестові сценарії. Результати перевірки документуються окремо.
